# Architecture and evidence model

Next.js 16 App Router / React 19 / strict TypeScript / Tailwind 4 / Inter / Lucide. XYFlow provides accessible graph navigation and pan/zoom. Dagre supplies deterministic top-down ranks; ELK was considered but not needed for this bounded graph. A selected right panel becomes a bottom detail sheet on small screens. An HTML list provides keyboard access independent of the canvas.

`data/ontology.ts` contains explicitly authored learning activities and prerequisites. `data/esco.json` contains the official source snapshot. `lib/engine.ts` computes a prerequisite topological order, detects cycles/unknown IDs, matches consented evidence and constructs the graph from the selected profile and destination. The ESCO group expands real source relationships separately. No model invents nodes.

Evidence weights are transparent heuristics: institution 1, employer .9, document .65, personal claim .35, inference .15, unknown 0. Local learning matches are supported at >= .65, partial at >= .35, uncertain above zero, otherwise missing. These categories support explanations; they are not probabilities, professional assessments or claims of mastery. The UI does not show misleading percentage probabilities. ESCO requirements use exact source-URI matches; local skills do not automatically count as equivalents. Formal verification requires authenticated source ingestion, which is not configured.

Milestone completion is self-reported and never changes source evidence. Learning estimates are authored planning ranges, not sourced course durations or guaranteed outcomes. User time availability changes week estimates. Costs, jurisdictional rules, programme entry and formal equivalence remain unknown unless sourced. The eligibility evaluator returns conservative requirement-by-requirement statuses and refuses stale sources. Public resource cards are not live job listings or eligibility assessments.

Passport v1 requires consent, source system, source record ID, timestamp and evidence classification. Imported issuer claims are downgraded to document support because uploading a file cannot authenticate an issuer. The demo is fictional, with no real university verification. Imports stay local; no source system is mutated. Documents containing unexpected fields are normalized, not executed. React escapes user strings. Resource links are application-authored HTTPS URLs.

Browser persistence is versioned and validated, isolated by browser origin, and exportable. It is not multi-user secure storage on a shared browser: use delete/reset before sharing a device. Exported files may contain personal information and should be handled accordingly. Local storage failures are reported on explicit save; export remains available. No telemetry or external AI processing is enabled.

The PostgreSQL migration defines normalized catalogue entities/relationships plus private profiles, evidence, roadmaps, nodes, edges, milestones, consent and audit records. Entity kinds cover institutions, courses, qualifications, occupations, opportunities and rules without asserting unavailable data. Catalogue writes are denied to application roles. Private tables use `auth.uid()` ownership RLS. Composite FKs prevent attaching another owner's graph or nodes. Browser writes cannot assert institution/employer verification. Audit records are generated by a constrained trigger and cannot be rewritten by users. Future tenant isolation needs an explicit membership model before institutional data ingestion; no tenant access is granted today.

Supabase auth is configurable and deliberately disabled without a dedicated project's public URL/key. The schema and authorization tests are implemented, but no hosted Supabase database or cloud roadmap sync has been connected. Public demo persistence is local. Existing Campus and Workspace accounts/databases are untouched.
