# Roadmaps 2.0 architecture audit

Baseline: fccb627. The existing shell, brand masks, design palette, XYFlow primitives, evidence categories and PostgreSQL ownership tests are reusable.

Observed limitations: the application imports a three-item destination array directly into its UI, schema and explanation endpoint. The official ESCO snapshot covers only three occupations and 69 skills. Ten authored learning skills feed all paths. Expansion appends two generic route nodes; it does not resolve alternative prerequisite paths. Official requirements appear as a flat group without a learning hierarchy. Progress is global rather than saved per roadmap. There is no document extraction, OCR, academic import, qualification profile or CV review. The explanation endpoint always returns a deterministic demo summary; the Groq adapter is unconnected. Supabase auth is optional and cloud roadmap persistence is absent. The original private schema and RLS tests exist but no hosted database is configured. Career comparison is three repeated cards. Campus integration is a boundary, not a live connection.

2.0 architecture: a versioned occupational index with source IDs/aliases/relations; server search and lightweight client results; a curated curriculum graph distinct from ESCO requirement edges; multidimensional evidence matching; explicit profile/academic/document claim schemas; local PDF/DOCX/OCR extraction with reviewed mappings; modular page components; deterministic teaching and practice with a budgeted provider-independent optional server gateway. Preserve the existing deployment, brand and privacy boundaries. Existing v1 JSON profiles are migrated rather than discarded. No course-title-only verification or credential inference is allowed.

External research access: the initial fresh requests to ESCO, roadmap.sh, Campus/Workspace and provider documentation were denied by the current network policy. Their domain additions are saved in the environment draft. Current source repositories are being inspected through the existing GitHub proxy. This is not evidence that the live references or providers were successfully reviewed on this run.

Foundation evidence: the pinned English CSV mirror at Y4SSERk/ESCO-csv2Graph commit 3b2d8e6a34c7f7b0da6e808518b32bb4767d41a3 contains 3,039 released occupations, 13,939 released skills, 67,622 essential and 61,382 optional relationships. All referenced skill IDs resolve. Against the previously retrieved official 69-skill sample, all IDs are present and 66 labels match exactly; label differences are retained as snapshot/version differences, not silently overwritten. Source file hashes and attribution are committed in catalogue-manifest.json. English is the available language in this mirror; current release and multilingual refresh remain unverified while official endpoints are blocked.

Latest Campus and Workspace source commits remain 82b020b53a97713740b9f3565a1e04666a4c760b and 2e7cda395f183dd289e77d22d4a8e59bdd5326e7. Campus's /courses/[id]/export route is faculty/admin-authorized CSV grade export, not a public student-record API; its integrations documentation explicitly states no Passport issuance/shared SSO. No source or database in those applications was modified.

The first expanded validation run passed 32 unit/database scenarios: source coverage and search, distinct rich curricula, prerequisite cycles and closure, weighted route search, document safety and source-span review, private-record ownership and immutable conservative AI budget reservations. Hosted services and external provider calls are not counted as verified by these local tests.
